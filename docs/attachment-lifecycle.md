# 附件生命周期与存储竞争

适用于单进程账号工作台。所有上传、读取、完成和删除仍检查账号与会话归属；附件不是共享知识库。测试使用隔离账号和临时数据库。

## 职责与事务

- `src/api/attachments.py` 负责 HTTP 参数、上传体和响应。
- `src/core/attachment_runtime.py` 负责接收与解析任务、解析名额、取消等待和失败收尾。
- `src/infra/attachment_store.py` 负责归属、状态、配额、文件补偿和恢复。
- `src/infra/sqlite_transactions.py` 提供会话创建与附件共用的显式写事务。取锁与提交各最多等待 1 秒，单次 SQLite 尝试不等待，重试间隔最多 5 毫秒。只重试 BEGIN 或同一事务的 COMMIT，不重新执行上传、解析或整个业务回调。

等待锁期间不持有认证提交守卫或取消许可锁；每次尝试重新核验。撤销先被确认，则未提交写入回滚；提交先完成，则保留已提交结果。历史、技能写入目前通过兼容适配共用提交守卫，尚未全部迁移为显式事务政策。

共享连接作用域覆盖打开、初始化后的访问和关闭，按所属资源转换 SQLite 错误；会话连接工厂初始化失败时负责关闭已经取得的连接。附件打开失败为 `attachment_unavailable`，会话准备打开失败为 `conversation_storage_unavailable`，不会因认证仍正常而报 `auth_unavailable`。原始异常保留在内部异常链，日志仅输出阶段、SQLite 代码及 request_id，不输出数据库路径、SQL 或底层异常文本。

## 接收、解析与结果未知

同会话的 `client_upload_id` 唯一。先只读查找，确需新增才取写锁，并在事务内复查。同 ID、相同内容返回既有记录；内容冲突或已删除返回冲突。原始文件、配额准入和记录插入各执行一次；提交失败补偿本次创建的文件。

提交接收记录后才启动解析。完成时再次校验归属、`generation` 与 `parsing` 状态；文本文件只写一次，提交失败补偿本次文本。取消会撤销提交许可并等待线程真正退出，再释放名额，防止迟到的 `ready`。

HTTP 响应丢失不意味着接收失败。前端保留结果未知状态，先显式核对；允许用户使用相同上传 ID 重试，但不会自动重放 POST 或解析。取消和删除不能承诺撤销已发生的外部副作用。

## 失败、删除与恢复

解析退出后执行幂等失败标记，只能将对应 generation 的 `parsing` 变为 `failed`，不能发布 `ready`。该内部维护允许在账号撤销后继续。持续锁阻止标记时，运行时保留待处理项并记录脱敏日志；显式状态核对或关闭时再尝试。进程重启后由 `recover()` 处理残留的 `parsing`。

收尾失败以领域异常传播：后台调用点记录并延期，显式核对保留本次 `attachment_storage_busy` 或 `attachment_unavailable` 分类，不再从一个布尔失败值猜测原因。只有收尾成功才移除待处理项；核对不会再次释放解析名额。

删除先提交 tombstone 和清理标记，再删除文件。清理只处理 `cleanup=1` 的记录；文件删除或数据库提交失败时保留标记和配额，后续列表刷新或启动恢复再次尝试。成功清理才释放已删除记录的占用。接收回滚后若文件补偿也失败，会记录警告，启动恢复清理没有数据库记录的孤儿文件。

附件响应中的 `cleanup_pending` 表示仍待清理，前端显示“文件清理尚未完成，请刷新核对”。失败附件不能选入问题；刷新通过 GET 核对，不重新上传。

| 错误码 | 含义 |
|---|---|
| `attachment_storage_busy` | SQLite 锁预算耗尽，HTTP 503；可释放竞争后显式核对或重试 |
| `attachment_unavailable` | 其他附件存储或文件 I/O 故障，HTTP 503 |
| `document_busy` | 解析名额不足，HTTP 503 |
| `document_processing_failed` | 未分类解析执行异常，不误报为输入无效 |
| `parse_interrupted` | 解析取消或启动恢复发现未完成任务 |

解析器已经明确识别的格式或内容错误保留其原错误码：非法编码、空文本、已知 PDF 格式错误及损坏的 DOCX 包仍为输入错误。进程启动、IPC 中断、无结果退出及未知解析异常为 `document_processing_failed`；诊断只记录异常类型或退出码，不记录文件内容。未成功启动的进程对象也会关闭，解析名额依原所有权释放。附件存储竞争不再映射为认证不可用；同期 `/auth/me` 可以正常返回 200。

## 验证与限制

`tests/offline/test_attachment_transactions.py` 覆盖接收、完成、删除、失败标记、恢复和清理的真实 BEGIN/COMMIT 锁竞争，以及持续锁、撤销补偿和关闭等待。`test_workspace_attachments.py` 通过真实 Cookie/CSRF 和 ASGI 请求验证短锁成功、持续锁准确 503、同 ID 核对及只解析一次。前端 `resources.test.tsx` 验证清理提示和仅 GET 刷新。

`tests/offline/test_attachment_error_contract.py` 覆盖真实认证 HTTP 的资源连接失败、连接初始化与关闭、认证数据库自身失败的原语义、收尾错误分类及恢复、进程/IPC 故障后的持久失败状态、资源释放、已知坏文件与未知异常的脱敏诊断。

任务登记和待收尾项仅在当前进程内保存，不提供跨进程任务协调或无限重试。启动恢复应在接收上传前执行。持续锁允许有界失败，测试通过不代表任何持锁时间都必须返回 202，也不能替代真实输入法、生产性能或回答质量验收。
