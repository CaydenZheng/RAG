# 内部售后 Agent 开发回归

内部评测复用应用中的 `SupportProfile`、`AgentHarness` 和检索工具。公开集合维持自己的协议；内部 Q/P 权重不是 MTRAG 官方评分标准。

## 运行与观测

`scripts/run_frozen_agent_eval.py --support-profile PROFILE --tasks TASKS --output OUTPUT` 保存实际回答、逐事件轨迹、模型可见输入、工具结果、请求耗时和服务商用量。数据、配置、模型及源码版本应在运行前冻结；失败记录也应保留。预热耗时与请求时延分开报告。

内部 JSON 规划默认要求完整 `understanding`，并校验当前动作与证据渠道是否一致。一次不合规输出可在正常规划预算内纠正，第二次失败则返回 `invalid_agent_understanding`。最终回答接收的是待核实的意图数据，不是已验证事实。这些约束保证结构可检查，不能保证业务语义正确。通用 Agent、公开集合和原生工具调用保留原协议。

本地逐片段过滤默认关闭。仅在重排成功且配置了 `rerank_min_score` 和 `rerank_filter_calibration_id` 时启用；BM25/RRF 降级不适用该阈值。必须先在查询—片段标注上检查误滤，不能把相关性分数当成整道题的可答性。观测会保留全部候选分数和实际返回片段，便于定位 Top-K 截取与过滤损失。

## 对保存结果评分

```powershell
.venv/Scripts/python.exe scripts/score_support_agent_eval.py `
  --packets PATH_TO_PACKETS --annotations PATH_TO_ANNOTATIONS `
  --rubric PATH_TO_RUBRIC --output NEW_SCORE_DIRECTORY
```

每例 packet 文件名为 `01-完整调用与结果.json` 等，包含运行器的 `result` 和 `events`。标注 JSONL 每行包含 `number`、`suite`、`required_facts`（id/text）、`critical`；可另给 `goal`、`known`、`missing`、`routes`、`stop` 和 `evaluation_audits`（id/criterion）。标注是评分依据，不应混进 Agent 的运行输入。

评分投影只保留一份必要事实、实际回答、意图和工具可见证据。完整模型输入仍在原 packet 中保存，避免把重复大段输入和未送给模型的原始结果混入评分上下文。实验环境完整性应单独检查，不作为用户回答的必答内容。

评分流程为：逐项事实/审查判断 → 缺陷及证据定位 → 缺陷主维度和严重程度 → 程序计算维度分与 Q/P。回答权重 A/B/C 为 5/3/2，过程权重 I/E/T 为 3/5/2；各维度取所属缺陷最低档，无缺陷为4，无法观察为 null。同一综合分内一个缺陷只归一个维度。生成或展示缺陷不能自动推出过程扣分。

每个缺陷需给出能在回答或轨迹找到的原文引用。声称某次调用前证据已充分时，必须定位该调用并引用更早的证据；可同时引用当次调用描述动作，但不能用后续结果倒推。机械校验不保证业务判断正确，仍须用人工已判样例校准。

当评分器把“扣分数”与“保留档位”混淆时，使用独立的严重程度复核阶段：先保存缺陷、证据及原始自动分，再隐藏旧数字分和版本身份，让复核器选择 `minor/material/major/critical` 标签。`src/evaluation/support_severity.py` 将其确定性映射为保留档位 `3/2/1/0`，重新校验后计算 Q/P。这一步不会重新生成 Agent 回答，也不改变冻结的权重。当前 CLI 完成第一阶段；标签复核与人工判据是单独的校准步骤，不能把 CLI 原始输出直接称为最终校准分。

人工仍有分歧时，另存适用范围、原自动判分和人工决定，对旧、新输出采用相同口径。报告必须区分原始自动分、标签复核分与人工校准分，并保留其文件及输入版本关系。已知样例上的一致性只能验证开发校准，不能证明评分器在未见案例上的准确率。

`--judge-thinking` 仅为评分调用显式开启 DeepSeek 思考模式，并扩大评分输出预算。它不改变 Agent 默认模式，强制跳过缓存，记录全部计费 Token，但不记录模型隐藏推理文本。不同评分模式和协议必须使用新输出目录，同版协议应同时重评旧、新 Agent 输出。

所有尝试均保留，只接受首次通过结构校验的评分；最多两次请求，校验失败的评分不进入均值。已保存评分绑定 packet 与协议哈希，输入变化后不能直接复用。自动分数还须经过语义校准；校准失败时应明确报告，不能删除低分、填补分数或把已暴露开发集当作独立测试集。

效率报告与质量分分开：调用次数、请求时延、服务商 Token、重试、缓存及观测缺失率。评分器成本另计。单次开发案例对照只能说明该次行为，不能证明性能提升的统计显著性。
