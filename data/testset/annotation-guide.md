# 人工核验与质量验收指南

当前 56 条 development 记录仍是未经人工核验的候选；没有 calibration 样本，final 为 0。本指南只定义工作流程，不授予现有样本人工核验状态，也不报告任何真实模型质量通过。

## 标注合同

沿用现有数据结构，不另建一套标注格式。每条记录由实际人工核验者检查：

| 字段 | 人工判断 |
|---|---|
| `id`、`question` | 稳定唯一标识；问题明确，无未说明的时间、实体或语境歧义 |
| `expected_behavior` | 相对于冻结语料应回答还是拒答，而不是相对于模型常识 |
| `ground_truth` | 回答应包含的必要事实与允许等价表述；拒答必须为 null |
| `task_types` | factual/entity/numeric/temporal/multi_fact/multi_hop/unanswerable/adversarial；多跳确实依赖多个来源 |
| `source_documents` | 来源路径或 URI、内容 SHA-256；来源确实属于冻结语料，不把私有凭据或敏感查询串写入 URI |
| `evidence_quotes` | 原文逐字证据；人工记录其来源和段落/位置，可在审核备注中说明，每个关键结论均有充分依据 |
| `provenance` | 如实保留生成方式、模型、Prompt、时间；未知填 unknown，不伪造 |
| `review` | 只有真实人工确认后填写 human_verified、reviewer、reviewed_at；备注记录歧义、修正、拒绝理由和证据位置 |
| `dataset_version` | 内容派生的版本，不手填冒充旧版本；更新内容后重算文件与 catalog 哈希 |

对拒答样本，检查整个相关语料范围，不能只因某一段没有答案就标为不可回答。对注入样本，核对期望行为仍以问题与证据为准，不将恶意指令当答案要求。模型筛查只能标为 ai_screened，不能替代人工核验。

## 三个划分与防泄漏

1. development 用于开发、失败分析和探索，允许 unverified，但任何结果都不能作为正式质量门槛。
2. calibration 必须人工核验，只用于阈值选择和参数校准。需要同时有可回答和拒答样本；当前校准器每模式至少要求 1 条 answer、3 条 abstain，这只是算法运行下限，不是可信样本规模。
3. final 必须人工核验，是独立冻结的最终验收集，不用于调参或选择阈值。

在看模型结果前，由负责人确定样本数量、各任务类型覆盖、语料范围、抽样规则与接受阈值，并写入受控验收计划。现在没有足够依据替负责人指定统计上可信的规模或虚构通过阈值。

同一 ID、同一问题不能跨划分；代码拒绝跨文件重复 ID 和跨划分忽略大小写/空白后的重复问题。语义改写、相同事实组合和证据家族泄漏仍需人工检查。共享知识语料本身不是泄漏，不应机械地禁止不同问题引用同一篇文章。

已经用于开发或校准的 56 条候选可以被人工核验后用于相应用途，但不能简单复制到 final 充当新的独立盲测。final 需另行设计并保留独立验收用途。样本晋级或移动时从旧划分移除重复记录，并重新计算所有版本；不留下跨划分副本。

## 冻结与执行

- 开发阶段可修订 development；校准仅运行 `--split calibration`，从 calibration 报告生成拒答阈值建议。校准器不再接受旧 final 报告，缺少逐样本人工核验信息的旧报告也需要重新生成。
- 将阈值、calibration_id 和模型绑定一起固定后，冻结 final、语料、索引、Prompt、代码 SHA、Provider/模型与评测配置。calibration/final 运行要求干净提交；dirty 候选仅执行离线合同测试，不冒充正式评测。
- 最终验收按预先定义的指标报告：检索 Recall@K/MRR/NDCG、答案正确性、引用实际支持、正确拒答/错误拒答/硬答、分任务结果与失败样本。现有引用指标只检查来源匹配和编号，不能单独证明引用片段蕴含答案；需人工或额外可信判定。
- 自动模型评分与人工判断分开报告。报告记录版本、样本量、运行环境、耗时、失败、未评分项和假设，不能将未运行项记为 0 或通过。
- 如果看过 final 结果后继续调参，该 final 就不再是新一轮独立盲测；需要新验收集或明确披露复用，不继续沿用“独立验收通过”的说法。

真实 Provider、活动索引或外部服务缺失时，记录阻塞；不把离线替身的合同验证当作真实回答质量。保存报告到受控本地产物目录，不将密钥、Token、私有参数或 OAuth 查询串写入文档、日志或公开报告。
